# 규칙

어기면 **나중에 고치는 비용이 큰** 것들. 스타일 문제는 [CONVENTIONS.md](CONVENTIONS.md)에 있습니다.

## 식별자

**한 번 부여한 Id/enum 값은 재사용하지 않습니다.**

삭제된 아이템의 Id를 다시 쓰면 옛 세이브가 엉뚱한 아이템을 가리킵니다. `PoolListSO`의 `PoolItem.Id`, `ItemDatabaseSO`의 대역별 커서가 이 규칙 위에 서 있습니다. "최대값 + 1"로 계산하면 마지막 항목을 지운 순간 깨집니다.

**아이템 Id는 타입별 대역에서 뽑습니다.** 대역은 `ItemDatabaseSO`의 `_idRanges` 표에 있고, 키는 **SO 파생 타입**입니다. `ItemCategoryType`으로 나누지 마세요 — 표시 전용이라 언제든 바뀌는데 Id는 안 바뀌므로 대역 밖에 남는 아이템이 생깁니다.

**대역이 꽉 차면 옆 대역으로 넘기지 않습니다.** Id를 주지 않고 에러를 냅니다. 조용히 넘기면 번호로 종류를 읽을 수 없게 되고, 그건 대역을 나눈 이유가 통째로 사라지는 것입니다. 대역을 늘리거나 새로 잡으세요.

**`전체 Id 재부여`는 세이브가 붙기 전까지만 쓸 수 있습니다.** Id 불변 규칙을 깨는 유일한 경로입니다. 세이브·네트워크에 Id가 한 번이라도 나간 뒤에는 절대 누르지 마세요.

**`WeaponStatType`은 0부터 빈틈없이 이어져야 합니다.** `WeaponStatus`가 배열 인덱스로 씁니다. 중간에 끼워 넣지 말고 뒤에 추가하세요. 쓰지 않게 된 값도 지우지 말고 자리를 비워둡니다(`MagazineSize`, `ReloadTime`이 그렇습니다).

**`EquipSlotType`의 폐기된 값은 재사용하지 않습니다.** 메카 전환으로 3, 4, 5, 7, 8, 9, 10이 비었습니다. 새 슬롯은 뒤에 붙이세요.

**`PoolType.cs`는 자동 생성 파일입니다.** 직접 편집 금지.

## 상태 되돌리기

**풀링 대상은 `OnDespawn`에서 모든 런타임 상태를 되돌립니다.** 체력, `TargetType`, 타이머, 이벤트 구독. 하나라도 빠지면 다음 스폰에서 이상한 상태로 시작하고, 원인 추적이 매우 어렵습니다.

**modifier를 걸었으면 `Dispose`에서 걷어냅니다.** origin 기반이라 `RemoveModifier(this)` 한 줄입니다.

**`ItemInstanceRegistry.Clear()`를 새 게임/월드 로드에서 호출합니다.** 정적이라 플레이 모드를 나가도 이전 판의 인스턴스가 남습니다.

## 멀티플레이 대비

최종 목표가 멀티플레이입니다. 나중에 뜯어고치기 가장 비싼 것들입니다.

**`Random.value` 직접 호출 금지.** 전투 판정(치명타, 상태이상 확률)과 맵 생성은 전부 **시드 기반**이어야 합니다. 절차적 생성은 시드만으로 재현 가능해야 합니다.

> 현재 위반: `DamageHandler`, `ConditionCastEffector`가 `UnityEngine.Random`을 직접 씁니다. 알고 있는 부채입니다.

**싱글턴에 플레이어별 상태를 두지 마세요.** 매니저는 조회와 수명 관리까지만. 월드 상태(아이템 인스턴스 레지스트리 등)는 프로세스당 하나라 정적이어도 되지만, 플레이어 상태가 전역에 있으면 서버 권한 구조로 못 옮깁니다.

> 주의: `PlayerInput`은 SO 에셋이라 지금 구조로는 **플레이어 하나만** 가능합니다.

**시뮬레이션과 표현을 분리하세요.** 이펙트·사운드·카메라 흔들림은 전부 이벤트 구독으로. 전투 로직이 직접 재생하지 않게.

## 데이터 무결성

**아이템 카테고리로 사용처를 판정하지 마세요.** `ItemCategoryType`은 표시 전용입니다. 장착·호환 판정은 파생 타입(`PlayerWeaponDataSO`)이나 명시적 슬롯/카테고리 목록으로 합니다.

**개체 상태가 있는 아이템은 `Inventory.Add`로 넣지 마세요.** `AddStack`을 쓰세요. `Add`는 `instanceId`를 잃어버리므로 에러를 내고 거부합니다.

**modifier의 origin은 참조 동일성으로 비교됩니다.** 박싱된 enum이나 struct를 origin으로 쓰면 제거가 안 됩니다.

## 조립

**부착 위치(소켓)는 프리팹에 Transform으로 둡니다. SO에 숫자로 넣지 마세요.** 소켓은 비주얼에 종속된 값이라, 스프라이트를 바꾸면 반드시 같이 바뀌어야 합니다. 숫자로 떼어놓으면 둘이 어긋난 채로 돌아가고 아무도 눈치채지 못합니다.

**앞 방향(+X) 보정은 `PartView` 루트에서 한 번만 합니다.** 소켓 좌표까지 같이 돌아가야 합니다. 소켓마다 따로 돌리면 규칙이 두 개가 되고, [INCIDENTS.md](INCIDENTS.md#총은-왼쪽을-보는데-총알은-오른쪽으로-나간다)와 같은 종류의 사고가 납니다.

**스탯 적용은 프리팹 유무와 무관하게 한 곳에서 합니다.** 프리팹이 안 꽂힌 파츠도 스탯은 적용되어야 아트 없이 밸런스를 볼 수 있습니다. 경로가 둘로 갈리면 "프리팹 있는 것만 해제 시 스탯이 안 돌아옴"이 반드시 납니다.

**조립된 유닛에 루트 Animator로 파츠 경로를 애니메이트하지 마세요.** 유니티 Animator는 경로 기반 바인딩이라 파츠를 교체하는 순간 끊깁니다. 전신 연출이 필요하면 **소켓만** 흔드세요 — 소켓은 어떤 파츠가 붙어도 항상 존재합니다.

## 물리 / 레이어

**캐스터가 LayerMask를 직접 들고 있으면 안 됩니다.** `TargetType`을 지정하고 `TargetLayerTableSO`가 마스크를 만들게 하세요. 둘을 따로 세팅하면 반드시 어긋납니다.

**레이어는 타게팅뿐 아니라 충돌 매트릭스에도 걸립니다.** 지상↔공중 전환으로 레이어를 바꾸면 지형 충돌도 같이 바뀝니다. 히트박스를 자식으로 분리해서 타게팅용과 물리 충돌용을 나누세요.
