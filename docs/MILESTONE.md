# 마일스톤

무엇을 언제 만들지. 시스템별 현황은 [STATUS.md](STATUS.md), 미뤄둔 이유는 [BACKLOG.md](BACKLOG.md)를 보세요.

## 지금 위치

**싸움이 양방향으로 돕니다.** 조립된 기체가 좌우 무기를 쏘고, 적이 스폰되어 쫓아와 때립니다. 판정 사슬이 양쪽 다 뚫렸습니다 — 플레이어 무기 → 투사체 → 캐스터 → `Health`, 그리고 적 → 캐스터 → `Health`.

**그런데 판이 끝나지 않습니다.** 플레이어 체력이 0이 되어도 아무 일도 일어나지 않고(`Health.OnDeadEvent`를 아무도 안 듣습니다), 맵이 없어서 끝도 경계도 없습니다. 총알은 벽을 뚫는데 벽이 없어서 증상이 안 보일 뿐입니다.

**다음은 M2입니다** — 맵, 지형 충돌, 죽음과 새 판. 여기서 미뤄둔 부채 세 개가 같이 해소됩니다.

## 하면서 정해진 것

### 편 가르기를 새로 넣었다

`TargetType`(지상/공중)은 유닛의 생김새지 소속이 아닙니다. 플레이어와 적이 **둘 다 지상 유닛이라 같은 레이어**라서, 적의 근접 공격이 레이어만으로는 다른 적까지 때렸습니다.

`FactionType`을 추가하고 캐스터가 때릴 편을 고르게 했습니다. **같은 편이라고 자동으로 빠지지는 않습니다** — PVPVE라 플레이어끼리도 싸웁니다.

### 적은 과열을 쓰지 않는다

적 공격은 쿨타임만 봅니다. 플레이어만 과열에 묶이는 비대칭이 실제로 거슬리는지 확인한 뒤에 정합니다.

### 길찾기는 안 넣었다

직선 추격입니다. 벽이 생기는 M2에서 실제로 걸리는 것을 본 뒤에 붙입니다.

## 남은 다듬기

코드가 아니라 **눈으로 맞춰야 하는 것**들입니다.

- **적 아트** — `Enemy_Test`는 기존 더미 스프라이트 그대로입니다
- **거리·선딜 수치** — 탐지 12 / 사정권 1.6 / 선딜 0.35 / 쿨 1.2는 임시값입니다
- **적끼리 겹친다** — 유닛 Rigidbody2D가 전부 Kinematic이라 밀어내기가 없습니다. 여럿이 한 점에 포개집니다. 고치려면 Dynamic으로 올리거나 분리 로직(boids separation)을 넣어야 하는데, 둘 다 플레이어 이동에도 영향이 갑니다

# M2 — 한 판이 끝난다

**목표** — 죽으면 다시 시작하고, 이전 판의 상태가 남지 않는다.

## 완료 조건

1. 플레이어 체력이 0이 되면 죽는다
2. 죽으면 다시 시작되고 **이전 판의 상태가 남지 않는다**
3. 투사체가 벽을 뚫지 않는다
4. 맵 밖으로 나갈 수 없다

## 작업 항목

### 맵

**절차 생성은 M4입니다.** M2에서는 손으로 만든 테스트 맵 하나면 충분합니다. 절차 생성부터 손대면 벽 충돌·스폰 위치·길찾기가 한꺼번에 엮여서 무엇이 문제인지 안 보입니다.

| 항목 | 담당 | 비고 |
|---|---|---|
| 테스트 맵 | **유니티** | Tilemap 또는 스프라이트 + Collider2D. 벽으로 둘러싸인 방 하나 |
| 지형 레이어 | **유니티** | 충돌 매트릭스 설정 |
| 투사체 지형 충돌 | 코드 | **결정 필요** — 아래 참고 |

### 죽음과 새 판

여기서 **미뤄둔 부채가 해소됩니다.**

| 항목 | 담당 | 비고 |
|---|---|---|
| 플레이어 사망 처리 | 코드 | `Health.OnDeadEvent`를 지금 아무도 안 듣는다 |
| 리스폰 / 새 판 | 코드 | `ItemInstanceRegistry.Clear()`와 `GameRandom.Reseed()`를 부를 유일한 자리 |
| 플레이어 스폰 흐름 | 코드 | HUD·조준점·카메라·발사 흔들림이 전부 `FindAnyObjectByType<Player>()`로 찾고 있다. 스폰이 생기면 `Bind()`를 밖에서 부른다 |

`ItemInstanceRegistry`는 정적이라 **플레이 모드를 나가도 이전 판의 인스턴스가 남습니다.** 지금은 월드 로드 개념이 없어 증상이 안 보일 뿐입니다.

## 정해야 하는 것

### 1. 투사체가 지형을 어떻게 인식하나

`TargetType`은 유닛 분류(Ground/Air)라 지형에 대응하는 값이 없습니다.

- **(A) `TargetType`에 지형 추가** — 캐스터 규칙 하나로 통일된다. 다만 지형은 `TargetBase`도 `Health`도 없어서 "타게팅 단위"라는 개념과 안 맞는다
- **(B) `Projectile`에 지형 전용 LayerMask** — 개념은 깨끗하지만 "캐스터가 LayerMask를 직접 들지 않는다"는 규칙의 예외가 생긴다

### 2. 죽으면 적재함을 어떻게 하나

유지 / 전부 떨군다 / 일부만 떨군다. **탈출형 루프라 이게 긴장의 핵심입니다** — 들고 나오지 못하면 잃는 구조여야 파밍에 무게가 실립니다. 다만 초반 테스트에는 유지가 편합니다.

**장착한 파츠는 적재함과 다릅니다.** 기체까지 잃는지, 적재물만 잃는지 따로 정해야 합니다.

# M3 — 손맛

**이벤트는 이미 다 뚫려 있고 듣는 쪽이 거의 없습니다.** `OnDryFireEvent`, `OnDamagedEvent`, `OnDeadEvent`가 전부 구독자 0입니다.

- 사운드 (`SoundPlayer`가 빈 스텁)
- 머즐 플래시·피격 이펙트
- 데미지 숫자, 피격 표시
- 파츠 애니메이션 — 부스터 화염·코어 아이들은 파츠별 Animator, 반동·과열 떨림은 DOTween ([PIVOT.md](PIVOT.md#애니메이션))
- 아이템 상세 패널 (`PartItemDetail`, `ItemPreview`)
- 과열 연출 — 게이지는 붙었지만 열기·증기·과열 경고음이 없다

**이미 붙은 것** — 발사 화면 흔들림(`WeaponFireCameraShake`), 총구 후퇴(`WeaponMuzzleRecoil`), 발사 애니메이션(`WeaponFireAnimator`).

**전투 로직이 직접 재생하지 않습니다.** 전부 구독으로 붙입니다 — 서버 권한 구조로 옮길 때 이 경계가 갈림길이 됩니다.

# M4 — 샌드박스

- 맵 절차 생성 (`GameRandom.World` 시드 기반. 시드만으로 재현 가능해야 한다)
- 도구 — 팔 슬롯을 무기와 공유하되 **판정은 처음부터 분리**. `HandActionBase.OnUsePressed`에 채굴을 붙인다
- 블럭 파괴·설치
- 자원 아이템
- 안전지대·격납고 — 로드아웃 교체, 수리, 탄종 지정. `EquipmentController.LoadoutLocked`를 켜는 주체 ([PIVOT.md](PIVOT.md#작업-순서) 10단계)
- 탈출 흐름 — 들고 나오기 성공/실패
- 적 풀링 (스폰이 잦아지는 시점)

# M5 — 저장과 성장

- 저장/불러오기
  - **개량(`UpgradeSO`)에 안정적인 Id가 없습니다.** 여기서 반드시 걸립니다. `ItemDataSO` 파생으로 올리거나 별도 Id 체계를 두어야 합니다
  - `ItemStack`(itemId·count·instanceId)이 저장 단위입니다
- 숙련도, 테크트리
- 언어 설정 저장

# M6 — 멀티플레이

지금은 만들지 않지만 **규칙만 지키고 있습니다.** ([RULES.md](RULES.md))

- 판정은 전부 `GameRandom` 시드 난수
- 싱글턴에 플레이어별 상태를 두지 않는다
- 시뮬레이션과 표현을 분리한다

이전 시점에 걸릴 것으로 이미 아는 것:

- **`PlayerInput`이 SO 에셋이라 로컬 1인 전용입니다.** 플레이어마다 다른 입력원이 필요합니다
- `Resources` 아래 아이템 전량 로드 → Addressables
