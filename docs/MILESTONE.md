# 마일스톤

무엇을 언제 만들지. 시스템별 현황은 [STATUS.md](STATUS.md), 미뤄둔 이유는 [BACKLOG.md](BACKLOG.md)를 보세요.

## 지금 위치

시스템은 깊은데 **플레이 루프가 없고, 그 위에 기획이 바뀌었습니다.**

전투 코어(스탯·데미지·상태이상·캐스터·투사체), 무기 한 줄(발사 4모드·탄약·모딩·내구도), 조준과 카메라, 아이템·인벤토리, 생존 수치, 로컬라이제이션까지 서 있습니다. 에디터 툴도 다섯 개 있습니다.

그런데 **맞힐 적도, 돌아다닐 맵도 없습니다.** `EnemyManager`와 `MapGenerator`는 한 줄짜리 빈 스텁이고, 죽어도 아무 일이 일어나지 않습니다.

2026-10-25에 **총에서 메카로** 기획이 바뀌었습니다([PIVOT.md](PIVOT.md)). 전투 코어·모딩·아이템 층은 거의 그대로 쓰이지만 플레이어 조작 층이 통째로 바뀝니다. **M1보다 전환이 먼저입니다** — 바뀔 조작 위에 적과 맵을 얹으면 두 번 엮게 됩니다.

## 전체 개요

| | 이름 | 한 줄 | 검증 |
|---|---|---|---|
| **M0** | 메카 전환 | 조작·무장·조립을 새 기획으로 옮긴다 | 조립된 기체가 좌우 무기를 쏜다 |
| **M1** | 한 판이 돌아간다 | 적·맵·죽음을 붙여 루프를 만든다 | 적을 죽이고, 죽으면 다시 시작한다 |
| **M2** | 손맛 | 이미 뚫어둔 이벤트에 표현을 붙인다 | 쏘고 맞히는 것이 재미있다 |
| **M3** | 샌드박스 | 맵 생성과 블럭 파괴·설치 | 지형을 바꿔가며 논다 |
| **M4** | 저장과 성장 | 세이브, 숙련도, 테크트리 | 이어서 할 수 있다 |
| **M5** | 멀티플레이 | 서버 권한 구조로 이전 | 둘이 같은 판을 본다 |

# M0 — 메카 전환

**목표** — 조립된 기체가 좌우 무기를 쏜다.

작업 항목과 순서는 [PIVOT.md](PIVOT.md#작업-순서)에 있습니다. 여기서는 완료 조건만 적습니다.

1. 장비 슬롯이 코어 / 좌팔 / 우팔 / 추진체로 재편되어 있다
2. 파츠를 끼우면 **기체 스탯이 실제로 바뀐다**
3. 코어 프리팹의 소켓에 팔·추진체가 붙어 기체가 조립된다
4. 좌클릭이 좌무기, 우클릭이 우무기를 쏜다
5. 재장전 없이 적재함에서 급탄되고, 과열이 연사를 제한한다
6. 핫바·소모품·정조준·투척이 코드에서 사라졌다
7. `Tools > Part Forge`로 스프라이트에서 파츠 SO + 프리팹을 만들 수 있다

**4번까지가 핵심입니다.** 5~7은 그 위에 얹는 것이라 순서를 바꿔도 됩니다.

# M1 — 한 판이 돌아간다

**목표** — 적을 죽이고, 죽으면 다시 시작한다.

## 완료 조건

이게 전부 되면 M1이 끝난 것입니다.

1. 적이 스폰되어 플레이어를 쫓아오고 때린다
2. 무기로 적을 죽일 수 있고, 죽으면 사라지며 아이템을 떨군다
3. 적에게 맞으면 플레이어 체력이 줄고, 0이 되면 죽는다
4. 죽으면 다시 시작되고 **이전 판의 상태가 남지 않는다**
5. 투사체가 벽을 뚫지 않는다
6. 맵 밖으로 나갈 수 없다

## 작업 항목

### 적

이미 있는 것 위에 얹습니다. `Agent` 컴포지션·`Health`·`TargetBase`·`HitBox`·`CircleCaster`·`DamageCastEffector`가 전부 재사용됩니다.

| 항목 | 담당 | 비고 |
|---|---|---|
| `UnitDataSO : ItemDataSO` | 코드 | 유닛도 아이템 데이터다. `ItemCategoryType.Unit`과 Id 대역 9000~9999가 이미 예약되어 있다 |
| `Enemy : Agent` | 코드 | `Player`와 대칭 |
| `EnemyMoveController` | 코드 | Rigidbody2D. 플레이어 이동과 같은 방식 |
| `EnemyAIController` | 코드 | 탐색 → 추격 → 공격 → 사망 |
| 사망 처리 | 코드 | `Health.OnDeadEvent` 구독 → 풀 반납 + 전리품 드랍 |
| `EnemyManager` | 코드 | 스폰 위치·개수·주기. 지금 빈 스텁 |
| 적 프리팹 | **유니티** | 풀링을 택하면 `Tools > Pool Manager`에 등록하고 Generate Enum |
| 적 SO 에셋 | **유니티** | `Tools > Item Creator`로 생성 후 Id 스캔 |

**AI는 상태 머신으로 갑니다.** 지금은 추격·공격 둘뿐이라 `if`로도 되지만, 원거리 적과 보스가 들어오면 반드시 갈아엎게 됩니다. 상태를 나누는 비용은 지금이 가장 쌉니다.

**공격 판정은 캐스터를 그대로 씁니다.** 적이 직접 데미지를 계산하면 플레이어 무기와 규칙이 갈립니다.

### 맵

**절차 생성은 M3입니다.** M1에서는 손으로 만든 테스트 맵 하나면 충분합니다. 절차 생성부터 손대면 벽 충돌·스폰 위치·길찾기가 한꺼번에 엮여서 무엇이 문제인지 안 보입니다.

| 항목 | 담당 | 비고 |
|---|---|---|
| 테스트 맵 | **유니티** | Tilemap 또는 스프라이트 + Collider2D. 벽으로 둘러싸인 방 하나 |
| 지형 레이어 | **유니티** | 충돌 매트릭스 설정 |
| 투사체 지형 충돌 | 코드 | **결정 필요** — 아래 참고 |

### 죽음과 새 판

여기서 **미뤄둔 부채 두 개가 같이 해소됩니다.**

| 항목 | 담당 | 비고 |
|---|---|---|
| 플레이어 사망 처리 | 코드 | `Health.OnDeadEvent`를 지금 아무도 안 듣는다 |
| 리스폰 / 새 판 | 코드 | `ItemInstanceRegistry.Clear()`와 `GameRandom.Reseed()`를 부를 유일한 자리 |
| 플레이어 스폰 흐름 | 코드 | HUD가 `FindAnyObjectByType<Player>()`로 찾고 있다. 스폰이 생기면 `Bind()`를 밖에서 부른다 |

`ItemInstanceRegistry`는 정적이라 **플레이 모드를 나가도 이전 판의 인스턴스가 남습니다.** 지금은 월드 로드 개념이 없어 증상이 안 보일 뿐입니다.

## 정해야 하는 것

작업 전에 확정할 것들입니다. 셋 다 나중에 바꾸면 비쌉니다.

### 1. 투사체가 지형을 어떻게 인식하나

`TargetType`은 유닛 분류(Ground/Air)라 지형에 대응하는 값이 없습니다.

- **(A) `TargetType`에 지형 추가** — 캐스터 규칙 하나로 통일된다. 다만 지형은 `TargetBase`도 `Health`도 없어서 "타게팅 단위"라는 개념과 안 맞는다
- **(B) `Projectile`에 지형 전용 LayerMask** — 개념은 깨끗하지만 "캐스터가 LayerMask를 직접 들지 않는다"는 규칙의 예외가 생긴다

### 2. 죽으면 적재함을 어떻게 하나

유지 / 전부 떨군다 / 일부만 떨군다. **탈출형 루프라 이게 긴장의 핵심입니다** — 들고 나오지 못하면 잃는 구조여야 파밍에 무게가 실립니다. 다만 초반 테스트에는 유지가 편합니다.

**장착한 파츠는 적재함과 다릅니다.** 기체까지 잃는지, 적재물만 잃는지 따로 정해야 합니다.

### 3. 적을 풀링하나 — **결정됨: 안 한다**

`Agent`와 `PoolableMono`는 둘 다 `MonoBehaviour` 직계라 `Enemy`가 **양쪽을 상속할 수 없습니다.** 풀링하려면 `Agent`를 `PoolableMono` 파생으로 올리거나(=`Player`까지 풀링 대상이 된다) 별도 핸들 컴포넌트를 두어야 하는데, 둘 다 정리 경로를 둘로 쪼갭니다.

**M1에서는 `Instantiate`/`Destroy`로 갑니다.** `Agent.OnDestroy`가 이미 컴포넌트 `Dispose()`를 부르므로 상태가 새지 않습니다. 풀링은 스폰이 잦아지는 M3에서 다시 봅니다 — 그때는 `OnDespawn`에서 체력·`TargetType`·타이머·이벤트 구독을 **전부** 되돌려야 하고, 하나라도 빠지면 다음 스폰이 이상한 상태로 시작해 원인 추적이 매우 어렵습니다.

## 진행 순서

| | 하는 일 | 검증 |
|---|---|---|
| **1차** | 맞고 죽는 적 (`UnitDataSO`, `Enemy`, 사망·드랍) | 쏘면 체력이 줄고, 죽으면 사라지며 아이템을 떨군다 |
| **2차** | 쫓아오고 때리는 적 (`EnemyMoveController`, `EnemyAIController`, 공격 캐스터) | 다가오면 쫓아와 때리고, 플레이어 체력이 준다 |
| **3차** | 맵과 지형 충돌 | 벽 밖으로 못 나가고 총알이 벽에 막힌다 |
| **4차** | 스폰과 죽음 (`EnemyManager`, 플레이어 사망·새 판) | 죽으면 다시 시작되고 이전 판 상태가 남지 않는다 |

**1차를 AI 없이 끊는 이유** — 무기 → 투사체 → `ProjectileCaster` → `DamageCastEffector` → `Health`로 이어지는 판정 사슬이 **실제 표적에 닿는 것이 처음**입니다. 여기에 AI까지 얹으면 안 맞을 때 배선 문제인지 AI 문제인지 갈라내기 어렵습니다.

## 범위 밖

M1에서 **하지 않습니다.** 넣고 싶어지면 M2 이후로 미루세요.

- 맵 절차 생성 (M3)
- 사운드·이펙트 (M2)
- 저장/불러오기 (M4)
- 원거리 적, 보스, 스폰 웨이브
- 근접무기·도구 (M3)
- 안전지대·격납고·탈출 흐름 (M3)
- 길찾기 (직선 추격으로 시작. 벽에 걸리면 그때 붙인다)

# M2 — 손맛

**이벤트는 이미 다 뚫려 있고 듣는 쪽이 없습니다.** `OnFiredEvent`, `OnDryFireEvent`, `OnDamagedEvent`, `OnDeadEvent`, `OnAmmoChangedEvent`가 전부 구독자 0입니다.

- 사운드 (`SoundPlayer`가 빈 스텁)
- 머즐 플래시·피격 이펙트·화면 흔들림 (`CameraShakeEffector`는 이미 있다)
- 데미지 숫자, 피격 표시
- 파츠 애니메이션 — 부스터 화염·코어 아이들은 파츠별 Animator, 반동·과열 떨림은 DOTween ([PIVOT.md](PIVOT.md#애니메이션))
- 아이템 상세 패널 (`PartItemDetail`, `ItemPreview`)
- 과열 게이지 연출

**전투 로직이 직접 재생하지 않습니다.** 전부 구독으로 붙입니다 — 서버 권한 구조로 옮길 때 이 경계가 갈림길이 됩니다.

# M3 — 샌드박스

- 맵 절차 생성 (`GameRandom.World` 시드 기반. 시드만으로 재현 가능해야 한다)
- 도구 — 팔 슬롯을 무기와 공유하되 **판정은 처음부터 분리**. `HandActionBase.OnUsePressed`에 채굴을 붙인다
- 블럭 파괴·설치
- 자원 아이템
- 안전지대·격납고 — 로드아웃 교체, 수리, 탄종 지정. `EquipmentController.LoadoutLocked`를 켜는 주체
- 탈출 흐름 — 들고 나오기 성공/실패

# M4 — 저장과 성장

- 저장/불러오기
  - **개량(`UpgradeSO`)에 안정적인 Id가 없습니다.** 여기서 반드시 걸립니다. `ItemDataSO` 파생으로 올리거나 별도 Id 체계를 두어야 합니다
  - `ItemStack`(itemId·count·instanceId)이 저장 단위입니다
- 숙련도, 테크트리
- 언어 설정 저장

# M5 — 멀티플레이

지금은 만들지 않지만 **규칙만 지키고 있습니다.** ([RULES.md](RULES.md))

- 판정은 전부 `GameRandom` 시드 난수
- 싱글턴에 플레이어별 상태를 두지 않는다
- 시뮬레이션과 표현을 분리한다

이전 시점에 걸릴 것으로 이미 아는 것:

- **`PlayerInput`이 SO 에셋이라 로컬 1인 전용입니다.** 플레이어마다 다른 입력원이 필요합니다
- `Resources` 아래 아이템 전량 로드 → Addressables

## 부채를 어디서 갚나

| 부채 | 갚는 시점 | 안 갚으면 |
|---|---|---|
| 장비 슬롯에 장착 효과가 없음 | **M0** (전환) | 기체 파츠를 끼워도 아무 일이 없다 |
| `ItemInstanceRegistry.Clear()` 호출처 없음 | **M1** (새 판) | 이전 판의 아이템 인스턴스가 남는다 |
| `GameRandom.Reseed()` 호출처 없음 | **M1** (새 판) | 시드 재현이 안 된다 |
| 투사체가 지형을 뚫는다 | **M1** (맵) | 벽 너머 적이 맞는다 |
| 개량(`UpgradeSO`) Id 없음 | **M4** (저장) | 세이브가 개량을 복원 못 한다 |
| `Resources` 전량 로드 | M5 전 | 시작할 때 전부 메모리에 올라간다 |
| `PlayerInput` 단일 SO | M5 | 두 번째 플레이어를 못 만든다 |
