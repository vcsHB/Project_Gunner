**싸움이 양방향으로 돕니다.** 조립된 기체가 좌우 무기를 쏘고, 적이 스폰되어 쫓아와 때립니다. 판정 사슬이 양쪽 다 뚫렸습니다 — 플레이어 무기 → 투사체 → 캐스터 → `Health`, 그리고 적 → 캐스터 → `Health`.

**판이 끝나고 다시 시작됩니다** (2026-11-22). 코어가 부서지면 비상탈출 — 기체와 적재물을 잃고 3초 뒤 새 판. 남는 건 안전 슬롯 한 칸입니다. 맵이 없어 끝도 경계도 없는 것은 그대로입니다(맵은 맨 마지막).

**지금은 M2 중입니다** — 활공/착륙·실드(2026-11-15), 부위파괴·필드 수리(2026-11-17), 전투 HUD·죽음과 새 판(2026-11-22)이 들어갔습니다. 판이 끝나고 다시 시작됩니다. 남은 것은 M3(손맛)·M4(적의 종류) 인게임 작업이고, **맵·지형 충돌은 인게임 내용을 다 해둔 뒤(M4 뒤) 맨 마지막**입니다. 여기서 미뤄둔 부채 세 개가 같이 해소됩니다.

**M3(손맛)도 겹쳐서 시작했습니다** — 재생 구조와 첫 이펙트 4종(피격·실드 피격·총구 화염·바닥 긁힘)이 붙었습니다(2026-11-15, [arch/feedback](arch/feedback.md)). 소리는 아직 에셋이 없습니다.

구조는 [ARCHITECTURE.md의 "적"](arch/enemy.md#적)과 [편 가르기](arch/combat-core.md#편-가르기-faction)로 옮겼습니다.

## 하면서 정해진 것

### 편 가르기를 새로 넣었다

`TargetType`(지상/공중)은 유닛의 생김새지 소속이 아닙니다. 플레이어와 적이 **둘 다 지상 유닛이라 같은 레이어**라서, 적의 근접 공격이 레이어만으로는 다른 적까지 때렸습니다.

`FactionType`을 추가하고 캐스터가 때릴 편을 고르게 했습니다. **같은 편이라고 자동으로 빠지지는 않습니다** — PVPVE라 플레이어끼리도 싸웁니다.

### 적은 과열을 쓰지 않는다

적 공격은 쿨타임만 봅니다. 플레이어만 과열에 묶이는 비대칭이 실제로 거슬리는지 확인한 뒤에 정합니다.

### 길찾기는 안 넣었다

직선 추격입니다. 벽이 생기는 M2에서 실제로 걸리는 것을 본 뒤에 붙입니다.

## 적도 메카가 됐다 (2026-11-15)

기본 적은 플레이어와 **같은 조립 경로**를 씁니다. `UnitDataSO.LoadoutTable`이 매번 굴려서 코어·좌팔·우팔을 뽑고, 팔에 든 무기로 쏩니다. 구조는 [ARCHITECTURE.md의 "적도 메카다"](arch/enemy.md#적도-메카다)에 있습니다.

`LoadoutTable`을 비워두면 조립하지 않습니다 — **메카가 아닌 적**(짐승·드론)은 근접 캐스터로 때립니다.

## 남은 다듬기

코드가 아니라 **눈으로 맞춰야 하는 것**들입니다.

- **적 아트** — `Enemy_Test`는 기존 더미 스프라이트 그대로입니다
- **거리·선딜 수치** — 탐지 12 / 사정권 1.6 / 선딜 0.35 / 쿨 1.2는 임시값입니다
- **적끼리 겹친다** — 유닛 Rigidbody2D가 전부 Kinematic이라 밀어내기가 없습니다. 여럿이 한 점에 포개집니다. 고치려면 Dynamic으로 올리거나 분리 로직(boids separation)을 넣어야 하는데, 둘 다 플레이어 이동에도 영향이 갑니다

# M2 — 한 판이 끝난다

**목표** — 기체가 실드로 버티다 부위별로 부서지고, 코어가 부서지면 죽는다. 다시 시작하면 이전 판의 상태가 남지 않는다.

**2026-11-15 사양 추가로 범위가 커졌습니다.** 실드·부위파괴·활공/착륙·게이지 표현·사망 연출이 M2에 합쳐졌습니다. 죽는 조건 자체가 부위파괴(코어 파괴)에 달려 있어서 따로 떼면 사망 처리를 두 번 만들게 됩니다.

## 완료 조건

1. 피해는 **실드가 먼저** 받고, 실드가 깨진 뒤에야 **맞은 부위**가 피해를 받는다 ✅
2. 실드는 전력이 충분하면 마지막 피격 후 일정 시간 뒤 서서히 찬다. 그 사이 맞으면 타이머가 처음부터 ✅
3. 팔이 부서지면 그 무기가 멈추고, **코어가 부서지면 죽는다** ✅
4. Space로 활공/착륙을 전환한다. 활공 중 고속 착륙은 미끄러지며 감속하고, 착륙 직후 1초간 다시 활공할 수 없다 ✅
5. 죽으면 조준점이 꺼지고 강한 흔들림과 함께 카메라가 뒤로 빠진다 ✅
6. 죽으면 다시 시작되고 **이전 판의 상태가 남지 않는다** ✅ (안전 슬롯만 남는다)
7. 투사체가 벽을 뚫지 않는다
8. 맵 밖으로 나갈 수 없다

## 권장 순서

1. **조작** — 다른 것과 엮이지 않고 바로 손으로 확인된다. 이동 속도를 먼저 맞춰둬야 나머지 수치를 잡을 수 있다
2. ✅ **실드 → 부위파괴** — 피해 경로를 바꾸는 작업. 적도 메카라 양쪽에 같이 걸린다
3. ✅ **전투 HUD(게이지 표현)** — 기체 실루엣, 서브게이지, 수리 진행(`PartRepairStatus`), 활공 상태(`PartGlideStatus`) (2026-11-22). 배치·스타일은 임시. 부위파괴·수리가 화면에 안 보여 테스트가 안 된다. **사망 연출이 HUD를 쓸 수 있어서 죽음보다 먼저** (2026-11-17 순서 변경)
4. ✅ **죽음 + 연출 + 새 판** (2026-11-22) — 비상탈출(기체·적재물 전부 잃음), 안전 슬롯, 착지 불가 지역(구조만). [arch/run](arch/run.md)
   - ✅ **지상에서 착지 불가 지역** (2026-11-23) — 걸어서는 가장자리에서 멈춘다. 미끄러져 들어가면 연료가 있으면 자동 활공, 없으면 추락
5. **맵·지형 충돌 — 맨 마지막** (2026-11-22). 인게임 내용(죽음·새 판, M3 손맛)을 먼저 다 해두고 맵을 붙인다. 완료 조건 7·8과 결정 1(투사체-지형)·활공 벽 넘기는 그때

### 게이지 표현 (서브게이지)

`SimpleGauge`에 `_gaugeIncreaseSubFill` / `_gaugeDecreaseSubFill` 필드가 **이미 있지만 아무도 안 씁니다.** 여기에 동작을 붙입니다.

| 게이지 | 줄어들 때 | 늘어날 때 |
|---|---|---|
| 체력 ✅ | 한 번 점멸하고 거의 즉시 | 서브게이지가 먼저 목표까지, 주 게이지가 따라감 |
| 연료 ✅ | 즉시 | 서브게이지 먼저 |
| 탄약 | 즉시 | 서브게이지 먼저 |
| 실드 ✅ | 체력과 같게 (2026-11-22) | 체력과 같게 |

**체력이 "시간에 걸쳐 차오르는" 건 UI가 아니라 회복 로직입니다.** 게이지는 목표값만 받고, 회복이 끊기면 목표값이 멈춥니다. UI가 회복 중단을 알면 안 됩니다.

탄약은 지금 **숫자 텍스트**(`PartEquipmentStatus._textCurrentAmmo`)라 게이지가 없습니다. 게이지를 새로 붙여야 합니다.

부위파괴가 들어가면 체력 게이지 하나로는 부족합니다. **코어 체력 게이지 + 기체 실루엣(부위별 상태)**이 기본안입니다.

|---|---|---|
| 테스트 맵 | **유니티** | Tilemap 또는 스프라이트 + Collider2D. 벽으로 둘러싸인 방 하나 |
| 지형 레이어 | **유니티** | 충돌 매트릭스 설정 |
| 투사체 지형 충돌 | 코드 | **결정 필요** — 아래 참고 |

### 죽음과 새 판

여기서 **미뤄둔 부채가 해소됩니다.**

| 항목 | 담당 | 비고 |
|---|---|---|
| 플레이어 사망 처리 | 코드 | **코어 파괴 = 사망.** `Health.OnDeadEvent`를 지금 아무도 안 듣는다 |
| 리스폰 / 새 판 | 코드 | `ItemInstanceRegistry.Clear()`와 `GameRandom.Reseed()`를 부를 유일한 자리 |
| 플레이어 스폰 흐름 | 코드 | HUD·조준점·카메라·발사 흔들림이 전부 `FindAnyObjectByType<Player>()`로 찾고 있다. 스폰이 생기면 `Bind()`를 밖에서 부른다 |

`ItemInstanceRegistry`는 정적이라 **플레이 모드를 나가도 이전 판의 인스턴스가 남습니다.** 지금은 월드 로드 개념이 없어 증상이 안 보일 뿐입니다.

## 정해야 하는 것

### 1. 투사체가 지형을 어떻게 인식하나

`TargetType`은 유닛 분류(Ground/Air)라 지형에 대응하는 값이 없습니다.

- **(A) `TargetType`에 지형 추가** — 캐스터 규칙 하나로 통일된다. 다만 지형은 `TargetBase`도 `Health`도 없어서 "타게팅 단위"라는 개념과 안 맞는다
- **(B) `Projectile`에 지형 전용 LayerMask** — 개념은 깨끗하지만 "캐스터가 LayerMask를 직접 들지 않는다"는 규칙의 예외가 생긴다

### 2. 죽으면 적재함을 어떻게 하나 — **전부 잃는다로 확정** (2026-11-22)

- **비상탈출 컨셉** — 기체를 버리고 나간다. 적재함과 **장착 파츠까지** 전부 잃는다
- **안전 슬롯 1칸** — 아무 아이템 한 칸 분량. 여기 든 것만 남는다
- 추가 결정: **착지 불가 지역**에서 강제로 내려앉으면 추락 = 사망. 구조는 지금, 배치는 맵 작업 때


유지 / 전부 떨군다 / 일부만 떨군다. **탈출형 루프라 이게 긴장의 핵심입니다** — 들고 나오지 못하면 잃는 구조여야 파밍에 무게가 실립니다. 다만 초반 테스트에는 유지가 편합니다.

**장착한 파츠는 적재함과 다릅니다.** 기체까지 잃는지, 적재물만 잃는지 따로 정해야 합니다.

### 3. 맞은 부위를 어떻게 아나 — **(A) 파츠별 히트박스로 확정** (2026-11-17)

구현: `HitBox.Part` = 붙은 소켓의 슬롯. **실드 원도 판정**(실드가 있는 동안만 켜짐)으로 같이 정했다. [arch/mecha](arch/mecha.md#부위파괴)


- **(A) 파츠마다 히트박스 콜라이더** (추천) — 파츠가 이미 프리팹이라 콜라이더를 붙이면 끝. 투사체가 맞힌 콜라이더 → 파츠. 다만 **팔이 코어 뒤에 가려지면 안 맞는다**는 게 그대로 플레이가 된다. 레이어·`TargetBase` 탐색이 파츠 자식까지 내려가야 한다
- **(B) 피격 방향으로 판정** — 기체 정면 기준 각도로 부위를 고른다. 콜라이더는 하나로 충분하지만, 눈에 보이는 것과 맞는 부위가 어긋날 수 있다

### 4. 실드 회복의 "전력이 충분하다" — **확정** (2026-11-15)

- **회복하는 동안 전력을 소모** (구현됨)
- 잠기거나 모자라면 **회복만 멈추고 타이머는 유지** (구현됨). `ShieldStatus._powerPerShield`

### 5. 실드와 부위파괴의 경계 — **확정** (2026-11-15)

- **그 타격은 실드에서 끝난다** (구현됨). 넘친 피해는 버린다. 실드는 방어력을 타지 않는다
- 실드가 0인 동안 맞으면 부위 피해와 함께 대기 타이머도 초기화된다 (구현됨)

### 6. 부위가 부서지면 — **확정** (2026-11-17)

- 추진체 → **활공·부스터 불가 + 감속(-40%)** (사용자 결정)
- 팔 → 무기만 정지. 떨어져 나가는 시각 연출은 M3
- 부서진 파츠는 **필드 수리로 되살아난다**(30%까지 차면)
- 파츠 체력과 내구도는 **별개** — 판마다 새로 찬다

아래는 정하기 전의 질문이다.


- 추진체 파괴 — 감속 / 활공 불가 / 둘 다
- 부서진 팔 — 무기만 정지인지, 파츠가 떨어져 나가는지(시각)
- 부서진 파츠는 그 판 동안 복구 불가인지, 필드 수리로 되살아나는지
- 파츠 체력과 아이템 **내구도**(`ItemInstance.Durability`)가 같은 값인지 별개인지 — 같으면 판이 끝나도 손상이 남는다

### 7. 필드 수리를 무엇으로 — **(A) 수리 키 하나로 확정** (2026-11-17)

R + `RepairKitDataSO`. 맞으면 끊기고 키트는 소모된다. [arch/mecha](arch/mecha.md#필드-수리-r)


**소모품 사용 경로가 메카 전환에서 사라졌습니다**(핫바·우클릭 사용 폐기). 좌우 클릭이 팔에 묶여 있어 수리 아이템을 "쓰는" 입력이 없습니다.

- **(A) 수리 키 하나** — 적재함의 수리 키트를 소모하며 시간에 걸쳐 회복. 키가 하나 늘어난다
- **(B) 수리 모듈** — 코어 모듈로 장착, 비전투 시 자동 회복. 입력은 안 늘지만 모듈 일반화(PIVOT 8단계)가 먼저 필요하다
- **(C) 픽업 즉시 적용** — 월드에서 주우면 바로 회복 시작. 가장 단순

### 8. 활공의 의미 — **공중 판정으로 확정** (2026-11-15)

- **표현은 몸체를 띄운다** (2026-11-17). 몸체·히트박스·총구·실드 원이 `Altitude`(0.6)만큼 화면 위로 뜨고, 그림자가 실제 위치에 남는다. 합의점: 보이는 곳에 맞고 보이는 곳에서 쏜다, 그림자가 서 있는 곳이 지형 기준 — [arch/input](arch/input.md#고도--몸체를-띄운다)

- 활공 중에는 **공중(`TargetType.Air`)** 이다 (구현됨). 지상만 노리는 캐스터는 안 닿는다. **지형(M2 벽)을 넘을 수 있는지는 아직 미정** — 맵 작업 때 정한다
- "고속 착륙"의 기준 — 착륙 순간 속도가 착륙 상태 최고 속도(부스터 포함)의 1.05배를 넘을 때로 구현. `_skidSpeedRatio`

# M3 — 손맛

**목표** — 쏘고, 맞히고, 맞는 순간이 눈과 귀로 느껴진다.

**이벤트는 이미 대부분 뚫려 있고 듣는 쪽이 거의 없습니다.** `OnDryFireEvent`, `OnDamagedEvent`, `OnDeadEvent`, `OnOverheatChangedEvent`, `OnShieldBrokenEvent`가 전부 구독자 0입니다. **빠진 것은 재생 구조**입니다 — `EffectBase`는 수명만 재는 껍데기고 `SoundPlayer`는 빈 스텁입니다.

**이미 붙은 것** — 발사·피격·착륙 화면 흔들림, 총구 후퇴(`WeaponMuzzleRecoil`), 발사 애니메이션(`WeaponFireAnimator`).

**M2와 겹쳐서 시작해도 됩니다.** 재생 구조(아래 1단계)는 M2의 어떤 작업과도 엮이지 않습니다. 다만 붙일 이벤트 중 사망·부위파괴는 M2가 끝나야 생깁니다.

## 완료 조건

1. 이펙트·사운드를 **한 줄로** 재생할 수 있고, 둘 다 풀에서 나와 끝나면 스스로 돌아간다
2. 연사 무기를 쏴도 같은 소리가 무한히 겹치지 않는다 (동시 재생 상한)
3. 발사 / 착탄 / 피격 / 실드 피격 / 실드 파괴 / 과열 / 빈 탄창에 이펙트와 소리가 붙어 있다 — **플레이어와 적 모두**
4. 볼륨을 BGM / 효과음 / UI로 나눠 조절할 수 있다
5. 전투 로직(`PlayerRangedWeapon`, `Projectile`, `Health` 등)은 이펙트·사운드를 **한 줄도 모른다**

## 권장 순서

1. ✅ **재생 구조** — `EffectPlayer` / `SoundPlayer` 풀, `SoundDataSO`, 귀(`AudioListenerFollow`). 테스트 이펙트·소리 하나씩으로 검증. **믹서 에셋만 남음**
2. ◐ **빠진 이벤트 뚫기** — 피격 위치·방향은 `DamageData`(`hitPoint`, `direction`, `blockedByShield`)로 해결. 투사체 소멸(사거리 끝·폭발) 이벤트는 남음
3. ◐ **무기 피드백** — 발사(총구 화염) ✅. 빈 탄창·과열·발사음은 에셋 대기
4. ◐ **피격 피드백** — 실드 피격·체력 피격 이펙트 ✅. 실드 파괴·복귀 연출 ✅ (2026-11-23, 이펙트·소리 칸은 비어 있음). **데미지 숫자는 띄우지 않는다** (2026-11-23 결정)
5. ◐ **기체 연출** — 착륙 미끄러짐 긁힘 ✅. 부스터 화염·활공, 파츠 애니메이션 남음
6. **UI** — 아이템 상세 패널, 버튼 호버

## 재생 구조 — 계획

> **1단계는 구현됐습니다.** 지금 코드의 설명은 [arch/feedback](arch/feedback.md)이 기준입니다. 아래는 계획 당시의 내용이고, 구현에서 바뀐 점은 이렇습니다 —
> 반납은 `stopAction` 콜백 대신 매 프레임 `IsAlive(true)`로 본다(자식 시스템까지 확실히 잡힌다). 루프 이펙트에는 수명 상한을 걸지 않는다. 이펙트에도 핸들(`EffectHandle`)이 있다.

### 원칙

- **전투 로직은 이벤트만 쏜다.** 재생은 구독자(피드백 컴포넌트)가 한다. 지금 카메라 흔들림이 이미 이 방식이다
- **무엇을 재생할지는 데이터가 정한다.** 무기·탄·코어 SO가 이펙트(`PoolType`)와 소리(`SoundDataSO`)를 들고 있다. `AmmoDataSO._projectilePool`이 이미 `PoolType`을 SO에 넣는 선례다
- **연출의 난수는 `UnityEngine.Random`을 쓴다.** 피치 흔들기·클립 고르기는 판정이 아니다. `GameRandom`에 섞으면 호출 순서가 달라져 판정 재현이 깨진다(`WorldItemSpawner` 흩뿌리기와 같은 이유) — RULES에 예외로 적어둔다
- **멀티에서는 각자 로컬에서 재생한다.** 서버는 이벤트(또는 상태 변화)만 보내고, 이펙트·소리는 받은 쪽이 튼다. 그래서 재생 함수는 위치·방향·데이터만 받는다 — 소유자 참조를 받지 않는다

### 이펙트 — `ParticleSystem` 기반

```
EffectPlayer.Play(PoolType, Vector2 position, float angle, Transform follow = null)
   └─ PoolManager.Get(type) → ParticleEffect
          OnSpawn: 자식 ParticleSystem 전부 Clear + Play
          끝나면 스스로 Release
```

| 항목 | 내용 |
|---|---|
| `ParticleEffect : EffectBase` | 루트 `ParticleSystem`의 `stopAction = Callback` → `OnParticleSystemStopped`에서 반납. 루프 이펙트는 `Stop()`을 불러야 끝난다 |
| 수명 안전장치 | `EffectBase._lifetime`을 상한으로 남긴다. 콜백이 안 오는 설정 실수가 있어도 풀이 마르지 않는다 |
| 따라가기 | 총구 화염처럼 붙어 다녀야 하는 것은 `follow`. **부모로 붙이지 않는다** — 무기가 풀로 돌아가거나 파괴되면 이펙트가 같이 사라지거나 끌려간다. 매 프레임 위치만 맞춘다 |
| 방향 | 이펙트 프리팹도 **+X가 정면**. 투사체·파츠와 같은 규칙 ([projectile](arch/projectile.md)) |
| 정렬 | `ParticleSystemRenderer`의 Sorting Layer / Order를 프리팹에서 지정. URP 2D라 기본값이면 스프라이트 뒤로 숨는다 |
| 등록 | 이펙트 프리팹 하나 = `PoolType` 하나. Pool Manager 창에서 등록 → Generate Enum. 프리셋에 넣어 미리 만든다 |

### 사운드 — `SoundPlayer` 풀

```
SoundManager.Play(SoundDataSO, Vector2 position) → SoundHandle
   ├─ 동시 재생 상한·최소 간격 검사 (데이터별)
   └─ PoolManager.Get(PoolType.SoundPlayer) → SoundPlayer
          AudioSource에 클립·볼륨·피치·믹서 그룹을 넣고 재생
          끝나면(클립 길이 / isPlaying) 스스로 Release
```

| 항목 | 내용 |
|---|---|
| `SoundPlayer : PoolableMono` | `AudioSource` 하나. **풀은 하나만** — 소리마다 프리팹을 만들지 않는다. 클립은 재생할 때 넣는다 |
| `SoundDataSO` | 클립 배열(무작위 선택), 볼륨, 피치 범위, 믹서 그룹, 2D/공간 비율, 루프 여부, **동시 재생 상한, 최소 간격** |
| 동시 재생 상한 | 연사 무기가 초당 15발이면 소리 15개가 겹친다. 데이터별로 세고, 넘치면 가장 오래된 것을 끊거나 새 것을 버린다 |
| `SoundManager` | 데이터별 재생 수를 세는 곳. **싱글턴이지만 플레이어별 상태가 없어서** RULES에 걸리지 않는다 |
| 루프 소리 | 부스터·활공·과열 경보는 끝을 알아야 한다. `SoundHandle`을 돌려주고 소유자가 `Stop()` — 소유자의 `Dispose`/`OnDespawn`에서 반드시 정리 |
| 믹서 | `Master / BGM / SFX / UI` 그룹. 볼륨은 노출 파라미터로 |
| BGM | 풀 밖. 전용 `AudioSource` 둘로 크로스페이드 |

### 빠진 이벤트

| 이벤트 | 어디에 | 왜 필요 |
|---|---|---|
| ~~착탄 `OnHitEvent(위치, 방향)`~~ | ~~`Projectile`~~ | **대신 `DamageData`에 실었다** — 피격 연출은 맞는 쪽(`HitFeedback`)이 낸다. 실드인지 몸체인지는 맞는 쪽만 안다 |
| 소멸 `OnExpiredEvent(위치)` | `Projectile` | 사거리 끝·수명 만료. 폭발탄은 여기서 폭발 이펙트 |
| ~~실드 피격~~ | ~~`ShieldStatus`~~ | `DamageData.blockedByShield`로 해결 |

**투사체는 풀링 대상이라** 착탄 이펙트를 투사체 자식으로 두면 반납과 함께 사라집니다. 이벤트를 받은 쪽이 `EffectPlayer`로 **따로** 띄워야 합니다.

## 정해야 하는 것

### 1. 피드백 컴포넌트를 어디에 붙이나 — **(A)로 확정** (2026-11-15)

의존이 망가지지 않는 선에서. 피드백 컴포넌트 → 무기/투사체 이벤트, 피드백 컴포넌트 → 재생 진입점. 무기·투사체는 피드백을 모른다.

**적도 같은 무기 경로를 씁니다.** 카메라 흔들림처럼 "카메라 쪽 한 곳에서 플레이어만 구독"하는 방식으로는 적의 발사음·총구 화염이 안 나옵니다.

- **(A) 무기·투사체 프리팹에 `WeaponFeedback` / `ProjectileFeedback`** (추천) — 자기 이벤트를 듣고 SO의 데이터로 재생. 적·플레이어 구분이 없다. 빠뜨리면 조용히 안 나오는 문제는 **Part Forge가 프리팹을 만들 때 붙여서** 막는다
- **(B) 씬에 전역 라우터 하나** — 기체가 조립될 때(`OnAssembledEvent` / `OnHandChangedEvent`) 무기를 찾아 구독. 프리팹은 깨끗하지만 구독 관리가 한곳에 몰리고, 스폰되는 모든 유닛을 추적해야 한다

### 2. 이펙트와 소리를 묶을까 — **(A) 따로 둔다로 확정** (2026-11-15)

- **(A) 따로 둔다** — SO에 `PoolType` 필드와 `SoundDataSO` 필드가 각각. 단순하다
- **(B) "큐(Cue)" SO로 묶는다** — 이펙트 + 소리 + 화면 흔들림을 하나의 에셋으로. 발사·착탄처럼 항상 같이 나오는 것은 편하지만 에셋이 하나 더 생긴다

처음엔 (A)로 가고, 같은 조합이 반복되면 (B)로 올리는 게 싸다.

### 3. 소리를 어디서 듣나 (AudioListener) — **기체 위치로 확정** (2026-11-15)

자식으로 붙이지 않고 위치만 따라간다(기체가 돌면 좌우가 뒤집히므로). `AudioListenerFollow`.

탑다운이라 카메라 위치에서 들으면 조준점 쪽으로 치우친 카메라를 따라 소리도 치우칩니다.

- **기체 위치에 리스너** — 내 기체 기준으로 좌우가 맞는다. 멀티에서도 "내 기체"가 기준이라 자연스럽다
- **공간 효과를 거의 안 쓴다** — 대부분 2D로 틀고 거리 감쇠만. 단순하지만 화면 밖 위협을 소리로 알 수 없다

### 4. 화면 밖 소리 — **들린다, 거리로 줄어든다로 확정** (2026-11-15)

들리는 범위는 소리의 크기로 정한다 — `SoundDataSO._audibleRange`. 범위 밖이면 재생하지 않는다.

적이 화면 밖에서 쏘는 소리를 낼지, 거리로 자를지. 낼 거면 거리 감쇠 곡선이 필요하고, 안 낼 거면 `SoundManager`가 재생 전에 거리로 걸러야 합니다.

# M4 — 적의 종류

**목표** — 메카가 아닌 적이 생긴다. 서 있는 포대, 떠 있는 기뢰, 나는 드론, 격추할 수 있는 미사일, 그리고 보스.

**바닥은 "단일 기체"입니다.** 지금도 `LoadoutTable`을 비우면 조립 없이 근접만 하는 적이 되지만, 총을 쏘지 못하고 걷는 것밖에 못 합니다. 아래 전부가 이 위에 섭니다.

## 완료 조건

1. 조립 없이 만든 적이 **자기 무기 하나**를 쏜다. 공격 방식(연사·정밀 단일 타격 등)이 여러 종류이고, 방식마다 피할 틈이 읽힌다
2. 터렛의 **공격 범위가 화면에 보이고, 지상을 쏘는지 공중을 쏘는지 범위만 보고 안다**
3. 부표에 닿으면 터진다. 쏴서 미리 터뜨릴 수 있다
4. 미사일을 총으로 격추할 수 있고, 격추되면 그 자리에서 터진다
5. 보스가 페이즈를 바꿔 가며 예고 있는 패턴을 쓰고, 잡을 수 있다
6. 잡은 적의 잔해에 다가가 상호작용하면 잔해 적재함이 열리고, **하나씩 드러나는 아이템**을 내 적재함으로 옮긴다

## 권장 순서

1. ✅ **단일 기체 구조** (2026-11-23) — 고정 무장, 다리 교체, 회전 포탑, 단일 기체 잔해. 테스트 터렛 `Enemy_Turret_Test`

### 터렛의 공격 범위 표시

**지상과 공중을 범위 모양만 보고 구분해야 합니다** (2026-11-23 요청). 제안 —

- **지상 범위** — 바닥에 깔리는 **실선 원 + 옅은 채움**. 유닛 아래에 그린다
- **공중 범위** — **점선 원, 활공 높이만큼 위로 띄워** 그린다(바닥 원과 어긋나 보인다). 활공할 때 몸이 뜨는 높이(`_glideHeight`)와 같아서 "떠 있는 쪽 판정"으로 읽힌다
- 둘 다 쏘면 두 원이 다 보인다. 색은 분류별로 하나씩
- 조준 중·사격 중이면 원이 진해진다

### 미사일 — 투사체 + 맞는 몸 (2026-11-23 확정)

무기가 탄으로 쏘고 풀에서 나오는 **투사체**입니다. 여기에 히트박스와 작은 체력을 달아 총알로 격추합니다. **격추되면 그 자리에서 폭발합니다** — 적 미사일을 적 근처에서 떨어뜨리는 플레이가 생깁니다.

- `TargetBase`/`Health`가 Agent 전제라 **"Agent 없이 맞는 것"** 경로를 새로 연다. 부표(기뢰)·부서지는 소품이 같은 길을 쓴다
- 캐스터가 대상을 접는 기준(`TargetBase`)을 건드리므로 기존 피격·중복 제거 회귀 확인
- AI는 미사일을 요격하지 않는다 (지금은)

### 보스

체력 비율로 페이즈, 패턴마다 예고, 화면 위 보스 체력바. 상태 클래스 구조가 원래 이걸 위해 나눠둔 것입니다.

**구조는 도착해서 정합니다** — (A) 큰 메카(기존 조립·부위파괴, 팔 2개 한계) / (B) 단일 기체 + 부위 일반화(이름 붙은 부위 여러 개, 부서지면 그 부위 무장이 꺼짐).

# M5 — 판 밖

**목표** — 판 밖이 생긴다. 로비에서 퀘스트를 고르고 기체를 편성해 나가고, 탈출하거나 부서져서 돌아온다.

```
타이틀 → 로비 ─┬ 퀘스트 게시판
               ├ 격납고 (진입 구성 편성 — 지금의 PendingLoadout)
               └ 창고 (판 밖 보관함 — 안전 슬롯·탈출 성공품)
       → 출격 → 필드 (퀘스트·파밍) → 탈출 / 기체 파괴 → 결과 → 로비
```

- **진행 흐름** — 지금의 "죽으면 3초 뒤 새 판"(`RunController`)이 "결과 화면 → 로비"로 바뀐다
- **로비** — 격납고(로드아웃 교체·탄종 지정, **파츠 상세 화면에서 무기 모듈 장착·개량**(2026-11-25 — 인벤토리에는 모듈 칸을 두지 않는다), `EquipmentController.SetLocked(false)`를 부르는 주체 — [PIVOT.md](PIVOT.md#작업-순서) 10단계), 창고, 퀘스트 게시판
- **퀘스트** — 데이터(SO) = 목표 목록 + 보상. 목표 유형: 처치(유닛 종류) / 파괴(구조물) / 회수(들고 탈출) / 도달 / 보스
  - 진행도는 게임 이벤트(유닛 사망·아이템 획득·탈출)를 듣는다 → **전역 게임 이벤트 통로**가 필요하다. 진행도는 플레이어별(RULES)
- **탈출** — 들고 나오기 성공/실패. 잃은 짐을 그 자리에서 다시 줍게 할지도 여기서
- 저장은 M7. 그전까지는 게임을 끄면 창고가 날아간다
