# 발사와 투사체

[아키텍처 목차](../ARCHITECTURE.md)로 돌아가기. 구현 현황은 [STATUS.md](../STATUS.md)에 있습니다.

## 발사와 투사체

```
PlayerRangedWeapon ──(발사 시점의 스탯을 값으로 복사)──▶ ProjectileLaunchData
                                                              │
                                                              ▼
                                                         Projectile
                                                              │ 매 프레임
                                                              ▼
                                                      ProjectileCaster ──▶ 이펙터
```

무기 스탯을 참조로 넘기지 않는 이유는, 총알이 날아가는 동안 무기를 바꾸거나 모듈을 갈아도 **이미 나간 탄의 위력이 변하면 안 되기** 때문입니다.

### +X가 앞이다 (논리)

**코드가 쓰는 정면은 +X 하나**입니다. `PlayerAimController.AimDirection`, 발사 방향, 캐스터, 투사체가 전부 그 위에 서 있고, 각도로 바꾸는 곳도 `Atan2(y, x)`라 0°가 +X입니다 — 수학 관례와 같아서 머릿속에서 보정할 게 없습니다.

**이걸 +Y로 바꾸지 마세요.** 방향을 나르는 것들은 전부 벡터라 정면 개념이 없고, 실제로 각도를 쓰는 곳은 기체 회전과 스프라이트 둘뿐입니다. 논리를 돌리면 각도를 만질 때마다 -90을 기억해야 합니다.

### 리소스는 위(+Y)를 보고 그린다 (표현)

유닛 리소스는 탑다운이라 위를 정면으로 그립니다. 논리(+X)와의 차이는 `FacingType`이 흡수합니다.

**회전 보정은 계층에서 딱 한 노드만 적용합니다.** 기체 루트(`MechaRotationController._facing`)가 -90°를 넣고, 그 아래 달리는 것(무기·모듈)은 **각자 보정하지 않습니다.** 둘 다 넣으면 두 번 걸려서 180° 틀어집니다.

> 이 전제는 "기체에 달리는 리소스는 전부 같은 방향으로 그린다"입니다. 깨지는 리소스가 하나 생기면, 그 프리팹 **안에서** 스프라이트 자식을 돌려 가두세요 — 바깥 규칙을 건드리면 안 됩니다.

**미러링은 회전과 다릅니다.** 부모가 돌든 말든 독립이라 겹쳐도 안전합니다. 그래서 미러링은 `HandActionBase`가 스폰 시 한 번만 처리합니다.

| | 축 | 대상 | 언제 |
|---|---|---|---|
| 회전 보정 | Z | 기체 루트 (`MechaRotationController`) | 매 프레임, 논리 각도에 더해서 |
| 리소스 방향 | X | 팔에 달리는 것 (`HandActionBase`) | 스폰 시 한 번 |
| 팔 미러링 | **Y** | 팔에 달리는 것 (`HandActionBase`) | 스폰 시 한 번 |

### 팔 리소스는 한쪽만 그린다

팔 파츠는 **한쪽 팔 기준으로만 그리고, 반대쪽에 달리면 뒤집습니다.** `_authoredArm`이 "어느 팔 기준으로 그렸나"고, 달린 슬롯이 다르면 미러링이 걸립니다.

**뒤집는 축은 Y입니다.** 기체 정면이 +X라서 좌우가 ±Y이기 때문입니다. X를 뒤집으면 좌우가 아니라 앞뒤가 바뀌어서 **총구가 뒤를 봅니다.**

총구와 모듈 장착점이 자식이라 스프라이트와 같이 따라옵니다 — 오른팔에 달면 총구 오프셋도 거울상이 됩니다. 뒤집힌 상태는 `IsArmMirrored`로 읽을 수 있습니다.

**발사 방향에서 부호를 뒤집는 식으로 맞추지 마세요** — 규칙이 두 개가 되는 순간 스프라이트·총구·모듈이 따로 놉니다. ([INCIDENTS.md](../INCIDENTS.md#총은-왼쪽을-보는데-총알은-오른쪽으로-나간다))

### CastPower — Agent 스탯만으로는 부족하다

`DamageCastEffector`는 원래 `Owner.AgentStatus.Damage`를 씁니다. 그대로 두면 무기 스탯도 탄종 차이도 전혀 반영되지 않습니다. 그래서 `CasterBase.Power`(nullable)에 발사자가 계산한 위력을 실어 보내고, 이펙터는 그게 있으면 우선합니다. 없으면 기존 동작 그대로입니다.

### 왜 경로를 훑는가

원형 질의만 하면 빠른 탄이 한 프레임에 적을 통째로 지나쳐 버립니다(터널링). `ProjectileCaster`는 직전 위치에서 현재 위치까지를 `CircleCast`로 쓸어 담습니다.

관통도 여기 있습니다. `CasterBase`의 중복 제거는 **한 번의 Cast 안에서만** 유효해서, 프레임을 넘겨 같은 적을 다시 때리는 것은 막아주지 못합니다. `ProjectileCaster`가 맞힌 대상을 기억했다가 `CanAffect`로 걸러냅니다.

### 발사 모드

타이머는 코루틴이 아니라 `Update`로 돕니다. 무기는 장비를 바꿀 때 파괴되는데, 파괴 도중 코루틴이 살아있으면 **이미 없는 무기가 한 발 더 쏩니다.**

점사(`Burst`)는 묶음이 도는 동안 쿨타임을 보지 않고 `BurstInterval`로 돌다가, 묶음이 끝난 뒤에 `AttackCooltime`을 한 번 겁니다.

산탄 각도와 치명타는 **`GameRandom.Combat`** 을 씁니다. `UnityEngine.Random`은 프로세스 전역이라 멀티에서 클라마다 탄이 다른 곳으로 날아갑니다.

### 투사체 프리팹 구조

폭발 캐스터는 직격 캐스터의 **형제**여야 합니다. 자식으로 두면 `CasterBase`가 `GetComponentsInChildren`으로 상대의 이펙터까지 집어갑니다.

```
Projectile
 ├ HitCaster  (ProjectileCaster + DamageCastEffector)
 └ Explosion  (CircleCaster + DamageCastEffector [+ ConditionCastEffector])
```
