# 입력과 조준 — 조준, 카메라, 팔 입력, 입력 차단

[아키텍처 목차](../ARCHITECTURE.md)로 돌아가기. 구현 현황은 [STATUS.md](../STATUS.md)에 있습니다.

## 조준

**마우스는 조준점의 절대 위치입니다.** FPS처럼 마우스 이동량으로 조준점을 미는 방식(상대 조준)을 쓰지 않습니다. 인벤토리가 커서를 그대로 쓰기 때문에, 커서를 잠그는 방식으로 가면 UI를 열고 닫을 때마다 입력 모드를 갈아타야 하고 그 경계에서 버그가 납니다.

그래서 조준점은 이렇게 만들어집니다.

```
커서 월드 좌표
   │ + 반동 오프셋 (발사 방향으로 밀렸다가 스스로 회복)
   │ 화면 안으로 자르기 (축별)
   ▼
AimPosition ──▶ AimDirection ──▶ 발사 / 무기 회전 / 조준점 / 카메라
```

**반동을 `AimPosition`에 직접 써넣으면 안 됩니다.** 다음 프레임에 마우스 값으로 덮여 사라집니다. 별도 오프셋으로 들고 있다가 더합니다.

이 모델의 결과를 분명히 해둡니다 — **반동은 스스로 회복하는 연출·명중률 효과이지, 플레이어가 마우스를 내려서 잡는 조작이 아닙니다.** 반동 제어를 실력 요소로 만들려면 상대 조준으로 가야 하고, 그건 커서 잠금과 입력 모드 전환을 동반합니다.

**무기 사거리로는 조준점을 자르지 않습니다.** 사거리 밖이라고 조준점을 안쪽에 붙들면 커서와 갈라져서 조작이 어긋난 것처럼 보입니다. 사거리 판정은 탄이 얼마나 날아가는지(`Range`)로만 합니다. `AimRange` 스탯은 카메라 거리나 명중률 감소 기준으로 쓰라고 남겨뒀고 **지금은 읽는 곳이 없습니다.**

### 화면 밖으로는 나가지 않는다

`AimPosition`은 카메라 뷰 안으로 잘립니다(`_viewPadding`).

커서는 원래 화면 안에 있으므로 **평소에는 걸리지 않습니다.** 반동으로 밀린 만큼과, 마우스가 게임 창 밖으로 나간 경우만 여기서 잡힙니다.

**여백은 비율이 아니라 거리입니다.** 비율(0.85 등)로 두면 화면이 클수록 여백이 같이 커집니다 — `orthographicSize 10`이면 가로로만 2.7유닛이 죽은 영역이 되고, 커서가 거기 들어가는 순간 조준점이 멈춰서 **커서에서 떨어져 나갑니다.**

카메라의 치우침 상한(`CameraFollowEffector._maxAimOffsetRatio`)도 같은 이유로 Vector2입니다. **둘 다 절대 거리가 아니라 각 축의 반너비/반높이에 대한 비율**이어야 합니다 — 절대 거리로 두면 해상도나 정조준 줌이 바뀌는 순간 다시 밖으로 나갑니다.

자를 때는 카메라의 **지난 프레임** 위치를 씁니다. 카메라는 `LateUpdate`에서 조준점을 따라오므로, 같은 프레임 값을 쓰면 서로를 참조하며 발산합니다.

### 정조준 — 기계장치만 남아 있다

**입력 연결은 끊겼습니다.** 우클릭이 우무기 발사로 가기 때문입니다. `PlayerAimController.SetAiming`과 카메라 줌은 **지우지 않고 남겨뒀습니다** — 자동조준 모듈이나 저격형 코어가 재사용할 자리입니다. 지금은 아무도 부르지 않으므로 `IsAiming`은 항상 false입니다.

남아 있는 것: 조준 보정 배율 0.5, 카메라 확대.

## 카메라

`CameraFollowEffector`가 **플레이어와 조준점 사이**를 봅니다. 플레이어를 정확히 따라가면 조준하는 쪽이 화면 가장자리라 멀리 있는 적이 안 보입니다. 치우치는 정도에는 상한(`_maxAimOffset`)이 있습니다 — 조준점을 멀리 끌고 가면 플레이어가 화면에서 밀려납니다.

### 순서가 어긋나면 조준점이 커서에서 밀린다

세 컴포넌트가 전부 `LateUpdate`에서 도는데, 유니티는 같은 단계 안의 호출 순서를 보장하지 않습니다. `AimExecutionOrder`로 값을 못박아 뒀습니다.

```
100  CameraFollowEffector  카메라가 먼저 움직인다 (지난 프레임 조준점을 향해)
200  PlayerAimController   옮겨간 카메라 기준으로 커서를 월드 좌표로
300  PlayerAimPoint        계산된 위치에 마커를 놓는다
```

조준을 `Update`에서 계산하면, 그 뒤 `LateUpdate`에서 카메라가 움직인 만큼 **조준점이 커서에서 밀립니다.** 카메라가 계속 이어서 따라오므로 밀린 채로 고정됩니다.

### 흔들림과 따라가기는 다른 Transform을 건드린다

**따라가기는 리그의 `position`을, 흔들림은 카메라의 `localPosition`을 씁니다.** 둘이 같은 오브젝트를 겨냥하면 매 프레임 서로를 덮어써서 **흔들림이 아예 보이지 않습니다** — 그리고 에러는 나지 않습니다.

씬 구조가 이 분리를 담당합니다.

```
Environment/Rendering/Camera
 └ CameraRig          ← CameraFollowEffector._rig  (월드 position)
    └ MainCamera      ← CameraShakeEffector._target (로컬 position)
 └ UICamera           ← 리그 밖. 따라다니지 않는다
```

두 컴포넌트는 `CameraManager`에 붙어 있습니다. `GetEffector<T>()`가 자식에서 모으기 때문에 **거기 있어야 찾아집니다.** 무엇을 움직일지는 각자 참조로 들고 갑니다.

### 발사 흔들림

`WeaponFireCameraShake`가 좌우 무기의 `OnFiredEvent`를 듣고 `Shake`를 부릅니다. 세기는 `Recoil` 스탯을 따릅니다 — 고정값으로 두면 모듈·탄종으로 반동이 달라져도 화면은 똑같이 흔들립니다.

**무기 프리팹이 아니라 카메라 쪽에 붙입니다.** 프리팹마다 붙이면 새 무기를 만들 때 빠뜨릴 수 있고, 빠뜨려도 그 무기만 조용히 안 흔들립니다.

좌우가 동시에 쏘면 `CameraShakeEffector`가 **센 쪽을 남깁니다.** 더하면 양손 연사에서 화면을 못 봅니다.

## 팔에 달린 것이 입력을 해석한다

입력은 **두 개뿐**입니다. 좌클릭(Primary)과 우클릭(Secondary). 배분은 **슬롯에 고정**되어 있습니다 — 좌클릭이 왼팔, 우클릭이 오른팔. 그 하나가 무슨 뜻인지는 달린 것이 정합니다.

| 달린 것 | Use |
|---|---|
| 총 | 발사 |
| 근접 | 휘두르기 |
| 도구 | 채굴 |

좌우 무장이 동시에 활성이라 각 팔은 **버튼을 하나만** 받습니다. 그래서 `HandActionBase`의 입력 창구도 `OnUsePressed` / `OnUseReleased` 하나뿐입니다. 정조준은 없어졌습니다 — 조준 보조가 필요하면 코어 모듈로 들어갑니다.

```
PlayerInput ──▶ PlayerHandController ──┬─▶ ArmLeft  (좌클릭)
                                       └─▶ ArmRight (우클릭)
```

**컨트롤러는 하나입니다.** 팔마다 컴포넌트를 붙이면 `Agent`가 타입당 하나만 등록하므로 한쪽이 통째로 조회되지 않습니다. `HandController`가 안에서 두 손을 배열로 들고 갑니다.

**만들고 붙이는 일은 `HandController`가 하고, 플레이어와 적이 같이 씁니다.** 파생이 다르게 하는 것은 [누가 방아쇠를 당기는가](enemy.md#방아쇠는-ai가-민다)뿐입니다.

**구독하는 쪽이 각자 "내가 나설 차례인가"를 판단하면 안 됩니다.** 조건이 여러 곳에 흩어지고, 결국 둘 다 반응하거나 아무도 반응하지 않는 상태가 생깁니다. 배분표는 `PlayerHandController` 한 곳에만 둡니다.

팔에 달 프리팹은 `IHandItemData`로 알려줍니다. 무기와 다른 계보가 섞일 수 있어 인터페이스로 뺐습니다 — 공통 베이스에 올리면 팔에 달 일이 없는 자원·블럭까지 프리팹 칸을 갖게 됩니다.

### 상태를 어디에 두는가

핫바가 없어지고 교체가 안전지대에서만 일어나므로, 팔에 달린 오브젝트는 **전투 중에 파괴되지 않습니다.** 그래서 런타임 상태를 `ItemInstance`에 올릴 이유가 줄었습니다 — 무기 오브젝트가 그냥 들고 있으면 됩니다.

| 상태 | 위치 | 이유 |
|---|---|---|
| 과열 | `WeaponHeatController` (무기 오브젝트) | 들고 있는 동안에만 뜨겁다. 뗄 때 식는다 |
| 점사·차지 진행 | `PlayerRangedWeapon` | 트리거를 놓으면 끝나는 값이다 |
| 모듈·개량·내구도·장전 탄종 | `ItemInstance` | 인벤토리에 넣어도 남아야 한다 |
| 잔탄 | 적재함 | 별도 수치가 없다. 재고가 곧 잔탄이다 |

기준은 하나입니다 — **인벤토리에 넣었다 다시 꺼냈을 때 남아야 하는가.** 남아야 하면 `ItemInstance`, 아니면 오브젝트입니다.
## 입력 차단

인벤토리를 열면 조준선이 사라지고 총이 나가지 않습니다. `UIInputBlocker`가 **세는 방식**으로 중간에 섭니다 — 인벤토리 위에 확인 창이 겹칠 수 있고, 하나만 닫혔다고 조작이 풀리면 안 됩니다.

`UIPanelBase._blocksGameplayInput`을 켠 패널이 뜨고 질 때 자동으로 밀고 뺍니다. 막는 쪽(패널)과 막히는 쪽(조준·발사)이 서로를 몰라도 됩니다.

**떼는 입력은 막지 않습니다.** 막힌 동안 뗀 것을 무시하면 버튼이 계속 눌린 상태로 남습니다. 막히기 시작하는 순간 `OnAttackReleased`를 대신 불러 연사와 차지를 풀어줍니다.

## 입력

`PlayerInput`은 SO이고 `Controls.IPlayerActions`를 구현해 **입력을 읽어 이벤트로 뿌리기만** 합니다. 게임 로직은 넣지 않습니다.

`OnDisable`에서 눌린 상태를 초기화합니다. SO는 플레이 모드를 나가도 살아있어서, 공격 버튼을 누른 채로 정지하면 다음 플레이에 눌린 상태로 시작합니다.

조준은 지금 마우스 전용입니다(`Look` 액션 없음). 패드 조준을 넣으려면 `Look`을 추가하고 `PlayerInput.PointerPosition` 자리를 갈아끼우세요.

**짧게/길게 누름 판정은 `PlayerInput`이 하지 않습니다.** 재장전 키는 눌림/뗌만 이벤트로 내보내고, "몇 초 이상이면 탄종 전환"은 `PlayerWeaponController`가 판단합니다. 시간 임계값은 게임 규칙이라 입력 리더에 들어가면 안 됩니다.

## 이동 — 착륙 / 활공

`PlayerMoveController`가 두 모드(`MechaMoveMode`)를 갖습니다. Space(`Glide` 액션, 옛 `Crawl`)가 토글입니다.

| | 착륙 | 활공 |
|---|---|---|
| 판정 | `TargetType` 기본값(Ground) | **`TargetType.Air`** — `TargetBase.SetTargetType`으로 레이어까지 바뀐다 |
| 속도 | `MoveSpeed` | `+_glideBonus` (Percent modifier, origin `_glideOrigin`) |
| 연료 | 부스터만 | 떠 있는 것만으로 `_glideFuelPerSecond`. 바닥나면 **강제 착륙** |

Shift 부스터는 두 모드 모두에서 따로 얹힙니다. modifier origin이 부스터(`this`)와 활공(`_glideOrigin`)으로 갈려 있어서 하나만 걷어낼 수 있습니다.

**미끄러짐** — 착륙 순간 속도가 착륙 상태 최고 속도(활공 배율을 걷어낸 뒤, 부스터는 포함)의 `_skidSpeedRatio`배를 넘으면 미끄러집니다. 진행 방향으로 `_skidDeceleration`만큼 감속하고, 입력은 방향을 `_skidTurnRate`(도/초)만큼만 꺾습니다. 속도가 최고 속도의 `_skidEndRatio`까지 떨어지면 정상 조작으로 돌아옵니다. 기준이 전부 **비율**인 이유 — 절대값이면 추진체마다 미끄러지는 길이가 달라집니다.

착륙 직후 `_glideLockAfterLanding`(1초) 동안은 다시 뜰 수 없습니다. 잠금이 풀리면 미끄러지는 중에도 뜰 수 있습니다.

**화면 흔들림은 이동이 부르지 않습니다.** `OnSkidStartedEvent`를 `SkidCameraShake`(`CameraManager` 오브젝트)가 듣습니다.

**죽은 뒤에는 판정을 건드리지 않습니다.** 사망으로 `TargetType.None`이 된 뒤에 착륙 처리가 `ResetTargetType()`을 부르면 시체가 다시 맞습니다.

### 고도 — 몸체를 띄운다

활공의 "떠 있는 느낌"은 **몸체를 화면 위로 띄워서** 냅니다 (2026-11-17 결정). 그림자를 떨어뜨리는 쪽보다 확실하게 떠 보입니다.

**높이는 로직이 가집니다.** `PlayerMoveController.Altitude`(0 → `_glideHeight` 0.6, `_liftDuration` 0.3초에 SmoothStep). 렌더 프레임마다 움직이도록 `Update`에서 올립니다 — `FixedUpdate`면 몸체가 계단처럼 뜹니다.

**합의점 — 무엇이 뜨고 무엇이 남나**

| 뜬다 (보이는 몸체) | 남는다 (실제 위치 = 그림자) |
|---|---|
| 비주얼, 파츠 히트박스, 총구, 실드 원 | Rigidbody, 이동, 벽·맵 경계(M2), 아이템 줍기 |
| 조준 원점(`PlayerAimController` — 원점에 `Altitude`를 더한다) | 카메라 추적 기준 |
| 적이 노리는 점(`TargetBase._aimPoint` = 몸체 루트) | |

- **보이는 곳에 맞고, 보이는 곳에서 쏜다.** 판정을 그림자에 두면 떠 있는 몸체를 쏴도 안 맞습니다
- **조준 원점을 같이 올려야 합니다.** 안 올리면 탄이 커서보다 고도만큼 위로 평행하게 지나갑니다
- 고도를 크게 잡을수록 그림자(벽 충돌 기준)와 몸체가 벌어집니다. 0.6은 그걸 감안한 값입니다

연출은 `GlideFeedback`(플레이어 루트)이 같은 값을 읽어서 그립니다 — 띄우기, 몸체 1.1배, 미세한 상하 흔들림(±0.04, 판정에도 걸리지만 무시할 크기), 그림자 축소·흐림, 활공 중 정렬 올리기(몸체 루트의 `SortingGroup`을 **뜬 동안만** 켬 → 지상 유닛 위에 그려진다). 카메라 줌아웃(×1.15)은 `CameraFollowEffector`가 `Altitude01`을 읽습니다. 이동은 연출을 모릅니다.

**띄우는 대상의 부모는 돌지 않아야 합니다.** 지금은 `Player/Root/VisualGroup/Root`(몸체)와 `Player/Shied`(실드). 코어 아래를 띄우면 "위"가 기체 회전을 따라 돕니다.
